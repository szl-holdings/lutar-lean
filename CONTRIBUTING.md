# Contributing to lutar-lean

Thank you for your interest in **lutar-lean**, the formal-methods source repository for SZL Holdings' Lean 4 governance proofs.

## Contribution model

SZL is maintained as a first-party solo-maintainer project. Owner-authored maintenance is admitted through GitHub-authenticated authorship, protected pull-request history, exact-head CI/security checks, and the immutable merge record. A DCO or `Signed-off-by:` trailer is not required for Stephen Lutar's first-party changes unless a future external agreement or repository rule explicitly requires one.

External contributions remain separate from that owner-maintainer rule. If you are a partner, customer, or collaborator working under a written agreement, follow that agreement and any repository controls that apply to the contribution. By submitting material, you confirm that you have the right to contribute it under Apache-2.0 and that required third-party notices and attribution are preserved.

## How to contribute

1. Open an issue describing the defect or proposed change.
2. Branch from the current protected `main` revision.
3. Keep the change narrowly scoped and preserve existing proof/evidence history.
4. Open a pull request and satisfy every applicable native CI, security, provenance, and review-thread requirement on the exact head.
5. Admit only through the repository's current protected merge path. Do not weaken proof guards or source-truth checks to obtain green status.

Documentation corrections can use the same path. Do not submit generated interpreter artifacts, local build output, credentials, or private evidence.

## Security disclosures

Do **not** open a public issue for a vulnerability. Follow [`SECURITY.md`](./SECURITY.md) and use the private security-reporting channel documented there.

## Contact

- GitHub issues: bugs, documentation gaps, and reproducible defects
- `security@szlholdings.com`: private security disclosures
- `stephen@szlholdings.com`: product, integration, licensing, or partnership questions
